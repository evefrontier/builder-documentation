# Interfacing with the EVE Frontier World

### Interfacing Overview

There are two primary paths for interfacing with the existing EVE World Modules:

* The write path, for calling EVE World System functions
* The read path, for fetching data from the EVE World Tables

Both paths are made more complex by the [Namespace rules](/broken/pages/bd0e0044e3ae8d41d8b432c0f74803e322b2e564#namespaces) of the MUD framework. The EVE World Systems and Tables are deployed in one Namespace, while builder Systems (when deployed) will be within a different Namespace.

For the write path, this entails:

* All EVE World Tables are only mutable via the existing EVE World System logic that interacts with them
* To make raw transaction calls to EVE World Systems, builders must either know how to generate the System [ResourceId](/broken/pages/bd0e0044e3ae8d41d8b432c0f74803e322b2e564#resourceids) and how to properly encode the `calldata` to interact with [world().call()](/broken/pages/bd0e0044e3ae8d41d8b432c0f74803e322b2e564#using-worldcall), or
* To enact the `world().fallback()` flow the builder needs a non-standard IWorld ABI which is auto-generated by MUD scripts. This ABI defines the _World_ function selectors and includes the Namespace, System, and function identifiers in its construction.

For the read path:

* The Table ResourceId should be generated or known, which means knowing the Namespace of the Table and the assigned Table Name

To help with the complexity of finding and generating ResourceIds, we provide interface libraries that expose standard function calls for the EVE World Systems and easy ResourceId lookups for Systems and Tables.

### Calling EVE World Functions

#### Interfacing via the Interface Libraries

Each Module contains an interface library located at its root. This file can be identified by the `*Lib.sol` naming convention.

For example, the `InventoryLib.sol` file can be found [here](https://github.com/projectawakening/world-chain-contracts/blob/develop/mud-contracts/world/src/modules/inventory/InventoryLib.sol). This library exposes the interface for all three Systems in the Inventory Module (`Inventory`, `EphemeralInventory`, and `InventoryInteract`).

Usage of the interface libraries requires some library importing and `use for` Solidity statements.

#### Calling System Functions directly via world.call()

Some builders may prefer the direct and standard method of `world().call()` to make cross-Namespace System calls. See how this is done [here](/broken/pages/bd0e0044e3ae8d41d8b432c0f74803e322b2e564#using-worldcall).

Helpful notes for this flow:

* All relevant System and Table NAME and NAMESPACE `constants` can be easily found in the local `constants.sol` file located at the root of each Module or in the `npm` package [@eveworld/common-constants](https://www.npmjs.com/package/@eveworld/common-constants) — NOTE: the `common-constants` package may be deprecated soon.
* If you have the deployed address of a System you can lookup its ResourceId using [SystemRegistry](https://github.com/latticexyz/mud/blob/next.17/packages/world/src/codegen/tables/SystemRegistry.sol).
* If you have the ResourceId of a System you can lookup its address using the [Systems Table getSystem](https://github.com/latticexyz/mud/blob/16121e8673adc72389a130cef64d73516c31d38c/packages/world/src/codegen/tables/Systems.sol#L101).
* If you have the ResourceId of a System, Table, or Namespace, you can extract both its Name and Namespace using [WorldResourceId](https://github.com/latticexyz/mud/blob/next.17/packages/world/src/WorldResourceId.sol).

### Fetching EVE World Data

#### Table Reads

Direct Table fetches require the use of the Namespace and Table Name to generate its ResourceId. Earlier examples in this documentation [used this method](/broken/pages/bd0e0044e3ae8d41d8b432c0f74803e322b2e564#example).

As a quality of life measure, we have implemented a `Utils.sol` library for each Module. It still requires a Namespace Name, but after that it exposes all of the Module's System and Table ResourceIds in one convenient place.

**Using Utils.sol**

Using the Utils library is a matter of importing it from the root of a Module and then `use as` for the `bytes14` Namespace Name where the Module's Systems and Tables have been deployed to.

**InventoryLib.sol and multiple Utils.sol integration example**

```solidity
pragma solidity >=0.8.24;

import { StoreSwitch } from "@latticexyz/store/src/StoreSwitch.sol";
import { IBaseWorld } from "@eveworld/world/src/codegen/world/IWorld.sol";

import { FRONTIER_WORLD_DEPLOYMENT_NAMESPACE as WORLD_DEPLOYMENT_NAMESPACE } from "@eveworld/common-constants/src/constants.sol";
import { Utils as InventoryUtils } from "@eveworld/world/src/modules/inventory/Utils.sol";
import { Utils as EntityRecordUtils } from "@eveworld/world/src/modules/entity-record/Utils.sol";
import { EntityRecordTable, EntityRecordTableData } from "@eveworld/world/src/codegen/tables/EntityRecordTable.sol";EphemeralInvItemTable
import { EphemeralInvItemTable } from "@eveworld/world/src/codegen/tables/EphemeralInvItemTable.sol";

import { InventoryLib } from "@eveworld/world/src/modules/inventory/InventoryLib.sol";
import { TransferItem } from "@eveworld/world/src/modules/inventory/types.sol";

import { EveSystem } from "@eveworld/smart-object-framework/src/systems/internal/EveSystem.sol";

contract InventoryInteractCall is EveSystem {
  using InventoryUtilsUtils for bytes14;
  using EntityRecordUtils for bytes14;
  using InventoryLib for InventoryLib.World;
  
  // Instantiate the Inventory Module interface object
  InventoryLib.World memory InventoryModuleInterface = InventoryLib.World({
    iface: IBaseWorld(worldAddress),
    namespace: WORLD_DEPLOYMENT_NAMESPACE
  });
  
  // on-chain itemId
  uint256 inventoryItemId = 31853211;
  
  // EntityRecord lookup
  EntityRecordTableData memory itemRecord = EntityRecordTable.get(
    WORLD_DEPLOYMENT_NAMESPACE.entityRecordTableId(),
    inventoryItemId
  );
  
  // lookup how many of this item I have in my ephemeral inventory
  uint256 quantity = EphemeralInvItemTable.get(
    WORLD_DEPLOYMENT_NAMESPACE.ephemeralInventoryItemTableId(),
    smartObjectId,
    inventoryItemId,
    _initalMsgSender()
  );
  
  // build the item data for this item
  InventoryItem memory itemOut = InventoryItem(
    inventoryItemId,
    _initalMsgSender(),
    itemRecord.itemId,
    itemRecord.typeId,
    itemRecord.volume,
    quantity
  );
  
  // build the item transfer array
  TransferItem[] memory itemsToTransfer = new TransferItem[](1);
  itemsToTransfer[0] = TransferItem(itemObjectIdOut, _initalMsgSender(), quantityOutputItem);
  
  // the interacting SSU smartObjectId
  uint256 smartObjectId = 11235813;
  
  // transfer from my ephemeral inventory to the SSU Inventory
  InventoryModuleInterface.ephemeralToInventoryTransfer(
    smartObjectId,
    itemsToTransfer
  );
}
```
